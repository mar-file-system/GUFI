\section{Quickstart for macOS}
This guide is a companion to the primary quickstart guide with
information specific to building and using GUFI on macOS. Please refer
to the primary quickstart guide and non-quickstart guides for more
details.

\section{Build From Source}
\subsection{Dependencies}
While macOS comes with some software for building code, much of it is
set up in ways that make building GUFI difficult, if not
impossible. Instead, \texttt{brew} packages should be used. The script
\texttt{contrib/CI/macos.h} should be used to install the
dependencies. The very last line of output from the script contains
extra paths to permanently add to your \texttt{PATH} variable.

\subsection{Configuration}
First create a build directory under the repository root
directory. This guide will create \texttt{build}. \texttt{cd} into it.
\\\\
\texttt{cmake}, which was installed by \texttt{contrib/CI/macos.h},
should be run first to configure the build. \texttt{cmake} tends to
pick up \texttt{AppleClang} for the C and C++ compilers, so explicitly
override them with the environment variables \texttt{CC} and
\texttt{CXX}.

\subsubsection{Additional \texttt{cmake} Flags}
Configuring GUFI on macOS requires one extra flag that is not required
in other environments: \texttt{-DCMAKE\_OSX\_SYSROOT=macosx}. If
\texttt{cmake} is unable to find OpenMP, try also passing in
\texttt{-DOpenMP\_Root="\$(brew --prefix libomp)"}.
\\\\
There are some additional flags that may be used when building on
macOS:
\begin{longtable}{|l|p{0.5\linewidth}|}
  \hline
  \texttt{cmake} Flag & Description \\
  \hline
  \texttt{-DCMAKE\_INSTALL\_PREFIX=<directory>} & \texttt{make
    install} target directory. Defaults to \texttt{/usr/local}. If
  installing as root, files will go into \texttt{/usr/local}. If
  installing as a user, files will \texttt{\$\{HOME\}/usr/local}. \\
  \hline
  \texttt{-DDEP\_INSTALL\_PREFIX=<directory>} & Location to place
  installs of bundled dependencies. Default is \texttt{deps} under
  the \texttt{build} directory, but everything will need to be
  rebuilt if the \texttt{build} directory is wiped. Recommend
  \texttt{\$\{HOME\}/.local}. \\
  \hline
  \texttt{-DDEP\_BUILD\_THREADS=<\#>} & Number of threads to use to
  build bundled dependencies. Default is 1. Recommend setting to
  higher value to build the bundled dependencies faster. \\
  \hline
  \texttt{-DCONFIG=<file>} & Path to file that user facing
  scripts (\gufifind, \gufils, etc.) need. Defaults to
  \texttt{/usr/local/etc/GUFI/config}. Change if installing as
  non-root-user. \\
  \hline
\end{longtable}

There are other flags that can be used to change target
directories. Do not change them on macOS.

\subsubsection{Example Configuration}
The basic configuration recommended for macOS is:
\begin{verbatim}
export SWHOME="${HOME}/.local"

CC="$(brew --prefix llvm)/bin/clang" \
CXX="$(brew --prefix llvm)/bin/clang++" \
cmake .. \
    -DCMAKE_INSTALL_PREFIX="${SWHOME}/GUFI" \
    -DDEP_INSTALL_PREFIX="${SWHOME}" \
    -DDEP_BUILD_THREADS="$(nproc --ignore 1)" \
    -DCONFIG="${SWHOME}/GUFI/etc/config" \
    -DCMAKE_OSX_SYSROOT=macosx
\end{verbatim}

\subsection{Build}
After \texttt{cmake} has completed succesfully, run \texttt{make}.

\subsection{Convenience Script}
The steps above are also encapsulated in the script
\texttt{contrib/build\_on\_mac.sh}. Run this script from the
repository root. The script was not set up to be sourced, so do not
source it as a shortcut to getting the environment variables.

\subsection{Install}
\subsubsection{Run Directly Out of \texttt{build}}
GUFI tools may be run from the \texttt{build} directory. Some values
should be added to environment variables:

\begin{itemize}
  \item Add \texttt{\$(realpath
    <DEP\_INSTALL\_PREFIX>/sqlite-vec/lib)} to
    \texttt{DYLD\_LIBRARY\_PATH}
  \item Add \texttt{\$(realpath
    <DEP\_INSTALL\_PREFIX>/sqlite-lembed/lib)} to
    \texttt{DYLD\_LIBRARY\_PATH}
  \item Add \texttt{\$(realpath
    <DEP\_INSTALL\_PREFIX>/llama.cpp/lib)} to
    \texttt{DYLD\_LIBRARY\_PATH}
  \item Add \texttt{\$(realpath build/src)} to \texttt{PATH}
\end{itemize}

\noindent If using the user facing scripts,

\begin{itemize}
  \item Add \texttt{\$(realpath build/scripts)} to \texttt{PATH}
  \item Add \texttt{\$(realpath build/scripts)} to \texttt{PYTHONPATH}
  \item Make sure the configuration file path exists. Since
    \texttt{make install} was not run,
    \texttt{\$(dirname~<CONFIG>)/config.example} won't exist
    yet for copying to \texttt{CONFIG}. Either reconfigure
    with an existing \texttt{CONFIG} or set the \texttt{PATH}
    variable in \texttt{build/scripts/gufi\_config.py} to the desired
    path.
\end{itemize}

\subsubsection{\texttt{make install}}
\texttt{make install} will install the required files into
\texttt{CMAKE\_INSTALL\_PREFIX}.
\begin{itemize}
  \item Executables will be placed in
    \texttt{<CMAKE\_INSTALL\_PREFIX>/bin}. This path should be added
    to \texttt{PATH}.
  \item Libraries (\texttt{*.dylib}) will be placed into
    \texttt{<CMAKE\_INSTALL\_PREFIX>/lib}, including the libraries of
    the bundled dependencies. This path should be added to
    \texttt{DYLD\_LIBRARY\_PATH}.
  \item If using the user facing scripts,
    \texttt{<CMAKE\_INSTALL\_PREFIX>/lib} should be added to
    \texttt{PYTHONPATH}.
  \item If using the user facing scripts, the configuration file will
    need to be placed at \texttt{<CONFIG>}. The example
    configuration file will be placed in the same directory with the
    name \texttt{config.example}.
\end{itemize}
If \texttt{CMAKE\_INSTALL\_PREFIX} and \texttt{CONFIG} were
not set during configuration, \texttt{sudo} will be required.

\subsubsection{PKGs}
\label{sec:pkgs}
Generate the primary PKG with
\begin{verbatim}
cpack -G productbuild -DCPACK_COMPONENTS_ALL=Local -B build
\end{verbatim}
The PKG will be placed in the \texttt{build} directory under the name
\\\texttt{GUFI-<VERSION>-Darwin.pkg}. If \texttt{productbuild} is not
found, run
\begin{verbatim}
xcode-select --install && cmake ..
\end{verbatim}
and try again.
\\\\
If administrative privileges are needed to build the PKG, either run
as root or set \texttt{CONFIG} to an accessible path
(\texttt{CMAKE\_INSTALL\_PREFIX} does not need to be set due to a
\texttt{cmake}/macOS interaction).
\bigskip
\hrule
\bigskip
\noindent To install the PKG, double click the file in
Finder. \texttt{installer} may be used from terminal but is not
recommended because \texttt{installer} always requires \texttt{sudo}.
\\\\
If the PKG is installed for all users (requires \texttt{sudo}), the
files will be placed into \texttt{PREFIX=/usr/local}.
\\\\
If the ``Install for me only" option is selected, the files will be
placed into \texttt{PREFIX=\$\{HOME\}/usr/local}. Add
\texttt{\$\{PREFIX\}/bin} to \texttt{PATH}.
\\\\
For either installation destination, do the following:
\begin{itemize}
  \item Add \texttt{\$\{PREFIX\}/lib} to
    \texttt{DYLD\_LIBRARY\_PATH}.
  \item If using the user facing scripts, add
    \texttt{\$\{PREFIX\}/lib} to \texttt{PYTHONPATH}.
  \item If using the user facing scripts, double check the
    \texttt{PATH} variable in \\
    \texttt{\$\{PREFIX\}/lib/gufi\_config.py} to make sure it is
    pointing to the expected place.
\end{itemize}

\section{Pre-Built PKGs}
Two pre-built PKGs are attached to the assets of
\href{https://github.com/mar-file-system/GUFI/releases}{each release
 on GitHub}. If proceeding with the PKGs, only download and install
the gufi PKG.
\\\\
If installing the PKG via the GUI, double clicking it might result in
a pop-up saying that the action was blocked. If this happens, run
\begin{verbatim}
xattr -r -d com.apple.quarantine <pkg path>
\end{verbatim}
Then double click on it again.
\\\\
To install via terminal, run
\begin{verbatim}
sudo installer -pkg <pkg path> -target /
\end{verbatim}
Once the PKG is installed, add \texttt{/usr/local/lib} to
\texttt{DYLD\_LIBRARY\_PATH}.
\\\\
If using the user facing scripts, also add \texttt{/usr/local/lib} to
\texttt{PYTHONPATH}.
\\\\
Note that the PKGs (and other artifacts) on GitHub are specific to
those releases/commits and do not get updated. To get the latest
changes into PKG(s), see Section~\ref{sec:pkgs}.
